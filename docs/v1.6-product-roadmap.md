# AgentHub v1.6 Product Roadmap

> **Status:** design only (no Service runtime code in this PR).
> **Baseline:** V1.5 Remote-Exec-1.0 + Lifecycle-1.0, git `main` @ `5022651`.
> **Audience:** product / ops owners deciding *what to build next*, and engineers mapping those bets onto this repo.
> **One-line intent:** a **sellable multi-device Agent product** — a registerable, schedulable, observable, (later) billable **execution plane** for Agent / human / DingTalk onto named office PCs.

This is a **product plan**, not a single-feature spec and not a Python-daemon spec. Long-running scripts on a designated PC are **one P1 workstream**. The product is the **fleet + job + package + artifact + alert** loop.

---

## 0. Executive summary

AgentHub already has a production-grade **control plane** (CAS task engine, DeviceLink outbound WebSocket, capability packages, HTTP artifact plane, LangGraph tools, DingTalk). What it does *not* yet have is the **sellable product**: a machine you can enroll, label, drain, and revoke; a job whose failure is traceable to *who / which machine / which package version* within minutes; tenancy/RBAC; SLA language; metering hooks.

**The sale is not “we run your Python.”** The sale is: scattered PC execution (Excel / 影刀 / Python / local apps) becomes an **execution plane** that Agents and humans can call like a service.

v1.6 ships as **product workstreams**, not a rewrite:

| Workstream | Why it exists | Shape |
| --- | --- | --- |
| **A. Reliability productization (P0)** | V1.5 ops tails: zombie ACCEPTED, download stall, I/O vs heartbeat, notification ≠ agent poll, DEVICE_BUSY | Harden `task/`, `artifact/`, `websocket/`, `worker/` |
| **B. Execution-plane semantics (P0)** | WS disconnect ≠ job done; write-side must not blindly redispatch; stale capability ads; package pin | Task state machine + resolver + worker ads |
| **C. Operator surfaces (P0/P1)** | Dashboard is an engineer console; no fleet groups, drain, catalog, alerts, run history | `static/index.html` + APIs |
| **D. Trust (P0 basic RBAC → P1 tenancy/secrets → P2 Vault/IdP)** | Shared admin token, fail-open, any-device-any-blob, secrets on disk | `auth/`, ACL, per-task injection |
| **E. Commercial hooks (P1/P2)** | MSP/ISV cannot sell without isolation + usage | tenancy, metering; quotas P2 |
| **F. Supervised processes (P1 only)** | One-shot Task ≠ resident process; Worker is a console | Worker-as-OS-service + optional `process/` plane |

**Productization bar (v1.6 P0 done):** enroll token → machine identity → labels → smoke task in **~30 minutes**; failure → **actionable DingTalk in ~5 minutes**; audit row: who / which machine / which package version. MTTD/MTTR are dashboard numbers, not slogans.

## 1. Product framing

### 1.1 Who buys, who uses

The unit of compute is a **named office PC** (Excel, 影刀/ShadowBot, local disks, **no inbound ports**). The 2026-09-15 incident (东方神舟 / 星舰X / 地平线1号 / 长征七号) is the seed fleet: designated machines, large xlsx, concurrent preprocess, humans in DingTalk. v1.6 must still work at that size **and** be sellable toward 50–500 machines without becoming Kubernetes.

| Persona | Job to be done | Today in this repo | Product they will pay for |
| --- | --- | --- | --- |
| **RPA ops** | Treat PCs as a **pool**: online, queue, retry, alert | Devices list + heartbeat; no groups/drain; DEVICE_BUSY is two policies | Fleet: register → group → health → drain → revoke |
| **Business owner** | SLA, traceable failures, “did payroll/audit run?” | DingTalk prose; no MTTD/MTTR; agent-only notify | Queue SLA metrics, 5-min actionable alert, audit trail |
| **Platform / Agent engineer** | Versioned capabilities, labeled workers, auditable artifacts | `capability_runtime` versions exist; no pin UX; artifacts exist, ACL weak | Immutable package pin + artifact ledger per task |
| **IT / compliance** | Enroll/revoke/audit; secrets not sprawling on disk | Registration codes + token hash; `capabilities.json` holds `robot_uuid`; params on WS | Enroll/revoke, audit export, **per-task secret injection** (P1) |
| **MSP / ISV** | Tenant isolation + usage metering | Single `users` row + one `AGENTHUB_ADMIN_TOKEN` | Tenancy (P1) + metering hooks (P1) + quotas (P2) |
| **Operator (data/finance)** | Kick a job, get a file, know if it failed | @ robot or ask whoever has the admin token | Dashboard + DingTalk as equal channels |
| **Device owner** | Leave the PC on | `python client/main.py` dies on logout | Worker-as-OS-service (packaging, not a new job type) |

### 1.2 Jobs to be done (the plane, not the daemon)

**North-star JTBD:** turn scattered PC execution into a **registerable, schedulable, observable, billable execution plane** for Agent / human / DingTalk.

Concrete jobs:

1. **Enroll a machine once.** Token → `device_id` identity (`client/identity.py`, `devices` table). Not a new cloud VM.
2. **Label and pool it.** “excel”, “yingdao”, “audit-night”. Schedule by tag (P1); designated device still wins when named (`CapabilityResolver` explicit-worker-first).
3. **Run a versioned job against named data.** Capability package + Artifact HTTP plane. Agent/human/DingTalk are just **intakes**.
4. **Queue, retry, and refuse blindly.** Read-side failures may retry; write-side / RPA must not re-run because the WS blipped. (V1.1 already has the *mechanism*; v1.6 must make it a **product policy**.)
5. **Observe and alert.** Progress, stall, busy, offline — without burning LLM tool budget.
6. **Revoke and drain.** Stop new work, finish or cancel in-flight, kill the token (`devices.revoke` exists; **drain does not**).
7. **Bill / isolate (P1+).** Metering hooks and tenant boundaries so an MSP can resell the plane.
8. **(P1, one workstream)** Keep a **long-running** script or the Worker itself alive — subordinate to 1–7.

### 1.3 Productization bar vs engineer-operated stack

| Bar | Engineer-operated today | Sellable v1.6 |
| --- | --- | --- |
| **Time to first smoke** | MySQL + Alembic + Funnel + `capabilities.json` character-match + DingTalk `.env` (`docs/运行手册-V1.5.md`) | Enroll token → identity → **labels** → smoke `echo` in **~30 min** |
| **Tenancy / RBAC** | One shared `X-Admin-Token`; empty token = open (`auth/admin.py`) | P0: fail-closed + roles `admin/operator/author`. P1: tenant. |
| **MTTD / MTTR** | Grep `server/logs` + `client/logs/worker.log`; ACCEPTED can sit 1800s | Stall detected in liveness window; DingTalk **actionable in ~5 min** |
| **Immutable packages** | `(name, version)` unique, DRAFT→PUBLISHED (`capability_runtime/service.py`) | **Pin** on the job; UI shows checksum; resolver honors pin |
| **Secrets** | Robot UUID in `client/worker/capabilities.json`; DingTalk secret in `.env`; task `params` on the WS envelope | P1: per-task injection, not on disk; WS carries handle not secret |
| **SLA language** | Timeouts exist (`timeout_at`, `CAPABILITY_DEFAULT_TIMEOUT=1800`) | Queue wait / run duration / success rate as **metrics**, not only a watchdog |
| **Metering** | None | P1: emit `task_id, tenant, device, capability, version, bytes, duration` (hook, not a billing engine) |
| **Failure UX** | CONFIGURED + maybe terminal if AgentRun already ended (`agent/notify.py`) | Every terminal → Alert + DingTalk: error code, device, package version, next action |
| **Audit** | `task_events` + `agent_tool_calls` exist | Operator query: **who / which machine / which package version** |

### 2.1 Product planes (sellable) mapped onto the four-layer code

The **product** exposes four planes. Internally AgentHub already has Reasoning/Control/Communication/Execution; v1.6 names the sellable cuts:

```
PRODUCT PLANES                         CODE (this repo)
─────────────                          ────────────────
Control   job + fleet + packages       server/app/task/  workflow/  command/
                                       capability_runtime/  device/  websocket/hub.py
```

**Preserve:** uncertainty lives only in the Agent. Workflow and Task are deterministic. Agent never touches WebSocket; seam is `server/app/task/device_link.py`. **Bytes never ride the chat or the WS** (`docs/LEARNING_GUIDE_0_to_1.md` §0.2).

### 2.2 DeviceLink / Worker (outbound fleet)

| Piece | Path | Product implication |
| --- | --- | --- |
| Device ≠ Connection | `server/app/websocket/hub.py` | Fleet UI shows **machine** health, not sockets |
| Dispatch to exactly one connection | `hub.select_worker_connection` | Extra WS clients must not double-run RPA |
| **Outbound-only** | `client/main.py`, README network model | Office NAT is the default; no inbound SSH/k8s |
| Heartbeat 15s / offline 45s | `client/heartbeat.py`, `websocket/heartbeat.py` | Online = connection + business heartbeat + `last_seen_at` |
| Reconnect jitter | `client/reconnect.py` | Failure storms after server restart already considered |
| Registration | `registration/service.py`, `core/security.py` | Enroll token exists; 40-bit / no rate limit (audit M2) |
| Revoke | `api/devices.py` revoke → WS 4403 | **Revoke exists; drain does not** |
| Execution bound to **process**, not WS | `client/worker/manager.py` docstring (PDF §108–§109) | **WS disconnect ≠ job done** — already a Worker invariant; product/docs must say it |
| Ledger idempotency | `client/worker/ledger.py` `attempt_id` UNIQUE | Write-side: reconnect **replays result**, does not re-run |
| Capability ads | `capability_runtime/worker_registry.py` `replace_worker_capabilities`; `last_seen_at` | Resolver (`resolver.py`) does **not** TTL-expire ads → **stale capability ads** |

**Gap:** `api/websocket.py` `_dispatch` uncaught → connection **1011** (audit H4). Product: “the PC dropped for no reason.”

### 2.3 Task engine (job state machine — read vs write fail)

| Piece | Path | Notes |
| --- | --- | --- |
| State machine | `task/state.py` | PENDING→…→RUNNING→terminal; STALE attempt-only; terminals irreversible |
| Event gates | `task/service.py` | Late result → `task.late_result`, never reopen |
| CAS dispatch | `task/dispatcher.py` | No duplicate attempts under concurrent monitors |
| Retry | `TaskService.request_retry` | New attempt, never mutate the old one (`state.py` header) |
| Monitor | `task/monitor.py` | PENDING redispatch, `timeout_at`, STALE reconcile |

**Write-side (do not blindly redispatch):** already encoded as CAS + ledger + late_result + STALE. v1.6 product work is to **classify** jobs: `risk_level` READ/WRITE/ACTION exists on capabilities (`capability_runtime/db_models.py`) and Agent tools (`policies.py`) but **dispatch retry does not consult it**. A 影刀 robot (`yingdao.py`) that already posted a transaction must not be auto-retried the way a checksummed download can.

**Read-side:** artifact checksum mismatch, stalled download, SENT-offline — retryable. Capability default timeout 1800s is a blunt instrument.

**Open tails (P0, not “later”):**

1. **ACCEPTED liveness (zombie).** `accepted_at` is written, unused. SENT-offline has 600s; ACCEPTED waits `timeout_at` (1800s). Audit H3; 地平线1号 17:45.
2. **DEVICE_BUSY is two products.** Command path **fails** the new task (`dispatcher.py` ~91–107). Capability path **defers** PENDING. Agent exposes `DEVICE_BUSY` (`agent/tools/base.py`).
3. **Accept ≠ running.** Worker accept-on-intake then unbounded queue (`manager.py`).
4. **`max_concurrency = 1`** — correct for GUI; product needs an explicit fail / queue / overflow-tag policy.

## 4. Competitive / adjacent — copy semantics, not products

AgentHub’s wedge is a **multi-device Agent execution plane** for office PCs, not an RPA Studio and not a job queue.

| Adjacent | They optimize | They miss | AgentHub unique |
| --- | --- | --- | --- |
| UiPath / AA / PAD | Bot design + licensed orchestrator | LLM/DingTalk → designated PC → xlsx loop; outbound-only simplicity | DeviceLink + capability ZIP + Agent tools |
| Celery / RQ | Server workers | NAT PCs, GUI/Excel/影刀 session | Named devices, Yingdao busy-check |
| Ansible | SSH config | GUI; NAT; conversational dispatch ([UiPath vs Ansible](https://apix-drive.com/en/blog/other/uipath-vs-ansible)) | Outbound WSS, lazy pull |
| **Kubernetes** | Kill pod / reschedule | **Do not copy:** killing a pod is not how you stop a GUI session. Semantics = **machine / session / job**, not replica | Device identity, ConnectionHub |
| n8n / Zapier | SaaS API | 500MB on 办公室电脑; 影刀 | Artifact + Yingdao |
| Computer-use agents | LLM clicks | Not reliable enough for repetitive desktop ([arXiv:2509.04198](https://arxiv.org/pdf/2509.04198.pdf)) | LLM **selects** a pinned capability |

### 4.1 Do NOT copy

- **k8s kill-pod / replica replacement** for a live Excel/影刀 session. Drain = stop *scheduling*, then cancel the **job** or stop the **OS process** — never “reschedule the machine.”
- **Heavy proprietary RPA Studio** as a prerequisite. Yingdao/Excel/Python stay the work engines; AgentHub orchestrates.
- **Force all process definitions into the cloud.** Packages are immutable blobs the Worker **pulls**; local `capabilities.json` / 影刀 robots remain valid. Cloud catalog is the *control* copy, not the only copy.

### 4.2 Borrow (semantics only)

| Borrow | Means here | Module |
| --- | --- | --- |
| **Labels / node selectors** | Device tags; schedule by pool (P1) while explicit device still wins | `devices` + `resolver.py` |
| **Drain / cordon** | `desired = DRAINING`: no new dispatch; in-flight finish or cancel; then revoke | **greenfield** on `device/service.py` |
| **Immutable artifacts** | Capability ZIP + Artifact checksums (already) | `capability_packages`, `artifacts` |
| Machine ≠ session ≠ job | Device / Connection / TaskAttempt | `hub.py`, `task/` |

**Moat to double down on:** WS control + HTTP data; capability packages; designated Worker; Agent tools as a narrow API; office-PC reality (影刀, GBK/UTF-8, Funnel).

**Do not try to beat in v1.6:** UiPath Studio, k8s autoscaling, general computer-use, a full public marketplace.

| **Pool / tag schedule** | Resolver: if no explicit device, pick by label ∩ capability ∩ not draining, then load | `resolver.py` | Explicit device still wins |
| **Drain** | `DRAINING`: dispatcher skips; in-flight finish; then revoke | `device/service.py`, `dispatcher.py` | Not k8s kill |
| **Queue SLA metrics** | Time in PENDING/ACCEPTED/RUNNING; success rate; busy defer count | `task_events` + `/api/metrics` | Language for business owners |
| **Tenancy** | `tenant_id` on users/devices/tasks/artifacts; admin scoped | extend `users`, every list API | Ceiling: one DB, row isolation — not sharded SaaS |
| **Metering hooks** | Emit usage facts (duration, bytes, capability, tenant) | **greenfield** events table or log contract | Not a billing engine |
| **Catalog UX + run history + workflow tab** | Publish/pin UI; who/machine/version query | `static/index.html` | APIs mostly exist |
| **Worker-as-OS-service** | Packaging so heartbeat survives logout | `client/packaging/` | Packaging, not a new job type |
| **Service/daemon for long-running scripts** | **One workstream only** — see §5.1 | `server/app/process/` | Must not eat the release |

### P1.1 Long-running processes (proportional)

`Task` is a one-shot with `timeout_at`. That is correct for 影刀 and Excel preprocess. It is **not** the product headline.

Do **not** overload `Task.status=RUNNING` for a days-long process.

Greenfield `process/` (optional name: Service): `ProcessSpec` / `ProcessInstance` on existing Envelope (`process.start|stop|status|logs`). Reuse capability packages + designated Worker.

Two named sub-deliverables:

1. **Worker-as-OS-service** — highest leverage for “product feels alive.”
2. **Long-running capability process** — push a resident script; status/logs/restart. **Part One of older requests, scoped as P1.**

## 6. Sequencing

```
P0-A stability (ACCEPTED, stall, heartbeat, notify, RBAC)
P0-B plane     (register/heartbeat UX, read-vs-write, pin, artifact ACL, alerts, labels, stale ads)
        └─► 30-min smoke + 5-min DingTalk  = sellable demo
P1 ops         pool/tag, drain, secrets, SLA metrics, tenancy, metering, catalog UX
P1 process     Worker-as-service, then optional process plane
P2             canary, Vault/IdP, classified retry, extra channels, MSP quotas
```

Dependencies: alerts need 0.1/0.5 codes; drain needs labels + dispatcher skip; metering needs tenant_id; process plane reuses Envelope — no second dispatcher.

## 7. Explicit non-goals

1. **Not** “AgentHub = a Python daemon.” One-shot Task + Workflow + Yingdao remain the default path.
2. **Not** k8s semantics (kill-pod, replica, cluster autoscaling) applied to GUI sessions.
3. **Not** a heavy RPA Studio, and **not** forcing every robot definition into the cloud.
4. **Not** a public capability marketplace with payments in v1.6 (pin + catalog UX only).
5. **Not** multi-region sharded SaaS. P1 tenancy = row isolation.
6. **Not** inbound SSH / Ansible replacement / computer-use LLM clicking 影刀.
7. **Not** Redis/MQ “because production” (V1.1 rejected it).
8. **Not** using the LLM tool loop as a job scheduler.
9. **Not** making the resolver smarter than explicit > label-pool > reporter > lazy-pull-by-load.
10. **Not** MSP quotas, Vault, or canary in P0.

## 9. Success criteria (v1.6 implementation, later PRs)

A v1.6 **release** is done when these are true — **not** when a long-running Python demo exists.

**P0 demo bar**

1. Someone who did not write this repo: enroll token → machine identity → label → smoke task in **~30 minutes**.
2. Failure of that job (or a real capability) produces **actionable DingTalk in ~5 minutes**: who (channel/user), which machine, which package version, error, task_id.
3. ACCEPTED cannot sit unexplained past the liveness window; UI shows stalled vs running vs queued vs draining.
4. Write-side / Yingdao jobs do **not** re-run because the WebSocket dropped; read-side download stalls do retry.
5. 500MB artifact cannot OOM the server or freeze heartbeats; worker download is device-scoped.
6. Package pin is visible and honored; stale capability ads are not scheduled.
7. Admin token cannot fail open on a public URL; basic RBAC on Dashboard.
8. `pytest tests` green without ignore flags.

**P1 sellable bar**

9. Pool/tag schedule + drain; queue SLA metrics (wait/run/success).
10. Per-task secret injection for at least Yingdao uuid.
11. Tenant isolation on list APIs; metering hook emitted per task.
12. Worker survives Windows logout (OS service).
13. Long-running process control exists **and** is documented as a separate plane — optional for the release headline.
