# AgentHub V1.7 从 0 到 1：配置部署运行目标程序全流程手册

> **适用版本：** V1.7 Worker Platformization（基线 main @ V1.6 Fleet-1.0 之后）
> **目标读者：** 第一次把一台干净 Windows 电脑接入 AgentHub，并让它运行既有 Python 业务程序的操作员
> **配套文档：** [V1.7_WORKER_PLATFORMIZATION.md](V1.7_WORKER_PLATFORMIZATION.md)（架构）、`docs/运行手册-V1.5.md`（V1.5 遗留单机操作）

---

## 0. 全流程总览

```text
① 部署服务端（一次性）
② 生成 Enrollment Token（管理员）
③ 新电脑 Bootstrap：注册 → 下载 Worker → 安装目录
④ 安装 Windows Service（开机自启、注销不掉线）
⑤ Worker 上线 → 自动上报环境快照
⑥ 发布目标程序：业务代码 + agenthub.yaml（零改造）
⑦ 派发执行：一次性任务（once）→ Artifact 输入/输出
⑧ 长期运行（service）→ 持久进程 start/stop/restart/日志
⑨ 观测：执行路径解释 / 环境漂移 / Worker 升级
```

## 1. 部署服务端（主电脑，一次性）

### 1.1 依赖

- Python 3.11+（服务端与客户端同机也可）
- MySQL 8.x（生产）或 SQLite（试用：`DATABASE_URL=sqlite:///server/storage/dev.db`）
- 服务端 Python 包：FastAPI / SQLAlchemy / uvicorn / pymysql / alembic / pyyaml / httpx / websockets

### 1.2 初始化

```powershell
cd d:\Websocket\server

# 1) 配置环境变量（或写 .env，两行必须设置）
#    DATABASE_URL=mysql+pymysql://user:pass@127.0.0.1:3306/datapilot?charset=utf8mb4
#    AGENTHUB_ADMIN_TOKEN=<自定义强随机串>          # 管理 API 令牌（admin 角色）
#    AGENTHUB_OPERATOR_TOKEN=<可选，操作员角色>     # 派发/取消/进程控制
#    AGENTHUB_VIEWER_TOKEN=<可选，只读角色>

# 2) 建表（全新库）
alembic upgrade head          # 当前 head = 0012（worker_environments / worker_processes / capability_versions.config）

# 3) 启动（本机试用绑定 127.0.0.1；局域网/公网必须绑定 0.0.0.0 且配置 ADMIN_TOKEN，否则管理面 fail-closed）
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

> **安全铁律（V1.6 0.7）**：`AGENTHUB_ADMIN_TOKEN` 为空时，管理 API 只在 `--host 127.0.0.1` 下开放；绑定 `0.0.0.0`（含 Tailscale）一律 401。

### 1.3 健康检查

```powershell
curl http://127.0.0.1:8000/api/health          # {"status":"ok",...}
curl -H "X-Admin-Token: $env:AGENTHUB_ADMIN_TOKEN" http://127.0.0.1:8000/api/devices
```

浏览器打开 `http://<server>:8000/` 即 Dashboard，右上角粘贴 Admin Token。

## 2. 生成 Enrollment Token（管理员）

Dashboard「设备」页 → **创建注册码**；或 API：

```powershell
curl -X POST -H "X-Admin-Token: $env:AGENTHUB_ADMIN_TOKEN" `
  -H "Content-Type: application/json" `
  -d '{"device_name": "办公室电脑03"}' `
  http://<server>:8000/api/device-enrollment/tokens
```

返回（注册码一次性、5 分钟过期）：

```json
{
  "enrollment_token": "DL-XXXX-XXXX",
  "expires_at": "...",
  "bootstrap_command": "python bootstrap.py --server http://<server>:8000 --token DL-XXXX-XXXX"
}
```

## 3. 新电脑 Bootstrap（Worker 自部署，§15-§20）

### 3.1 拿到 Worker 安装器

新电脑只需要仓库里的 `client/` 目录（或由管理员从 `GET /api/bootstrap/latest` 下载 ZIP 发过去）：

```powershell
# 方式 A：直接下载服务器打包好的 Worker 包（含 agenthub 运行时全部 client 代码）
curl.exe -o agenthub-worker.zip http://<server>:8000/api/bootstrap/latest ^
  -H "X-Admin-Token: $env:AGENTHUB_ADMIN_TOKEN"
Expand-Archive agenthub-worker.zip C:\AgentHub\bootstrap

# 方式 B：git clone 整个仓库，使用 client\ 目录
```

### 3.2 一键接入

```powershell
cd C:\AgentHub\bootstrap
python bootstrap\bootstrap.py --server http://<server>:8000 --token DL-XXXX-XXXX --download-worker
```

bootstrap 脚本（stdlib-only，无第三方依赖）会：

1. 用 Enrollment Token 调 `POST /api/devices/register` 换取 **device_id + device_token**（之后长期使用 device_token，enrollment token 即废弃）；
2. 把身份写入本机 identity 目录（`%USERPROFILE%\.devicelink\` 或 `DEVICELINK_HOME`）；
3. `--download-worker` 时从 `/api/bootstrap/latest` 下载 ZIP、校验 `X-Checksum`，解压到 `C:\ProgramData\AgentHub\worker`。

### 3.3 目录约定（§20）

```text
C:\ProgramData\AgentHub\
├── worker\        # Worker 程序本体（可被 updater 原子换名）
├── config\        # 身份与配置
├── workspaces\    # 每次执行/每个进程的 input|output|logs
└── logs\
```

> 不要把 Worker 数据放在桌面/用户目录 —— 用户注销会影响运行。

## 4. 安装 Windows Service（§21/§58）

### 4.1 方式 A：sc.exe 脚本（推荐）

```powershell
# 管理员 PowerShell
cd C:\AgentHub
.\scripts\install_worker_service.ps1 `
  -PythonExe C:\Python311\python.exe `
  -MainPy C:\ProgramData\AgentHub\worker\main.py `
  -ServerUrl http://<server>:8000
Start-Service AgentHubWorker
```

### 4.2 方式 B：pywin32 包装

```powershell
pip install pywin32
python client\service\windows_service.py install
python client\service\windows_service.py start
```

### 4.3 验收（§58）

- **重启 Windows** → 服务 Automatic 启动 → Worker 自动上线；
- **注销用户** → Worker 仍在线（Dashboard 设备点常绿）；
- 断网恢复 → 指数退避重连，任务结果由本地 Ledger 补报，不重跑。

## 5. 环境快照（§22-§28，自动）

Worker 每次连接自动上报 `worker.environment`（无需操作）：

- 机器：hostname / OS / 架构 / CPU cores / 内存 / 磁盘剩余
- 运行时：本机 Python 版本列表
- 自动化：影刀 RPA 检测（安装目录+版本）
- AgentHub：Worker 版本 + **SHA256 指纹**（变化 = Environment Drift，服务端日志会标记 `DRIFT`）

查看：

```powershell
curl -H "X-Admin-Token: $env:AGENTHUB_ADMIN_TOKEN" `
  http://<server>:8000/api/devices/<device_id>/environment
```

Dashboard：设备页 → **环境** 按钮（同时显示该机的持久进程）。

## 6. 发布目标程序：业务代码 + agenthub.yaml（§2-§5，零改造）

### 6.1 准备包目录

既有的 Python 项目**不改一行代码**，复制为包目录并新增一个文件：

```text
my_processor/
├── main.py             # 原样保留：python main.py --input ... --output ...
├── processors/         # 业务代码原样
├── requirements.txt    # 原样（Worker 会为其创建独立 venv）
├── manifest.json       # 平台契约（固定格式，见下）
└── agenthub.yaml       # ★ V1.7 唯一需要新增的声明
```

**manifest.json**（平台身份，name 必须三段式、与 agenthub.yaml 一致）：

```json
{
  "name": "data.preprocess_excel",
  "version": "1.0.0",
  "runtime": "python",
  "entrypoint": "main"
}
```

**agenthub.yaml**（如何运行它，与文档 §4 对应）：

```yaml
name: data.preprocess_excel
version: 1.0.0

runtime:
  type: python

execution:
  mode: once                     # once=一次性任务；service=长期进程

entrypoint:
  command: main.py               # 相对包根（禁止绝对路径/穿越）
  args:
    - "--input"
    - "${INPUT_DIR}"
    - "--output"
    - "${OUTPUT_DIR}"

workspace:
  input_dir: input
  output_dir: output
  log_dir: logs

environment:
  variables: {}

resources:
  estimated_duration_sec: 600    # 冷启动基线（历史数据会逐步替代它）
  memory_mb: 4096

restart:
  policy: never                  # service 模式可用 on-failure/always
  max_restarts: 5
  backoff_sec: 10
```

### 6.2 打包上传（ZIP：manifest.json + agenthub.yaml + 业务代码）

```powershell
Compress-Archive -Path my_processor\* -DestinationPath my_processor.zip
curl.exe -X POST -H "X-Admin-Token: $env:AGENTHUB_ADMIN_TOKEN" `
  -F "file=@my_processor.zip" `
  http://<server>:8000/api/capabilities/data.preprocess_excel/versions

curl.exe -X POST -H "X-Admin-Token: $env:AGENTHUB_ADMIN_TOKEN" `
  http://<server>:8000/api/capability-versions/<version_id>/publish
```

服务端上传时会校验 manifest 并合并 agenthub.yaml（进 `capability_versions.config`），执行器在 Worker 侧再次校验。

### 6.3 验证「零改造」

本地直接跑（不经过 AgentHub）仍然成立：

```powershell
cd my_processor
python main.py --input D:\data --output D:\out
```

AgentHub 执行时只是把 `--input/--output` 换成 Worker Workspace 路径 —— 程序不知道 AgentHub 存在（§5）。

## 7. 一次性执行（execution.mode=once，§7/§61）

### 7.1 输入数据注册

```powershell
# 数据源在服务器上（Dashboard「数据源」页扫描注册）；或 Worker 上传
curl.exe -X POST -H "X-Admin-Token: $env:AGENTHUB_ADMIN_TOKEN" `
  -F "file=@data.xlsx" http://<server>:8000/api/artifacts
```

### 7.2 创建任务（Dashboard / Agent / API 三入口等价）

```powershell
curl.exe -X POST -H "X-Admin-Token: $env:AGENTHUB_ADMIN_TOKEN" `
  -H "Content-Type: application/json" `
  -d '{
        "name": "预处理-9月",
        "execution_type": "CAPABILITY",
        "steps": [{"command": "data.preprocess_excel", "params": {}}],
        "input_artifacts": [{"artifact_id": "art_xxx", "role": "input"}]
      }' `
  http://<server>:8000/api/tasks
```

执行链：**执行路径选择** → Preflight → pin 校验 → 派发 → Worker 拉包/拉数据 → 业务程序运行 → 产物扫描（`workspace.output_dir`）上传 → 产物 Artifact → 钉钉/Dashboard 通知终态。

### 7.3 执行路径解释（§42）

任务详情页事件 `task.sent` 里带：

```json
"execution_path": {
  "estimated_completion_sec": 455.0,
  "predicted_runtime_sec": 420.0,
  "confidence": 0.82,
  "explain": "ETA 455s = queue 0s + transfer 35s + startup 30s + runtime 420s (confidence 0.82)",
  "reasons": ["history-8-runs", "transfer-900MB@25MB/s", "startup-30s", "execution-path-resolver"]
}
```

规则：历史成功运行优先于配置基线（样本 ≥5 完全采信）；BUSY 机器的 ETA 计入其当前任务剩余时间；数据量按 `EXECUTION_TRANSFER_MBPS`（默认 25）计传输成本；同分按 device_id 定序。显式指定设备时直接采纳但仍做 Preflight（Python 不兼容会明确失败，不偷偷换机，§54）。

## 8. 长期运行（execution.mode=service，§8-§13/§62）

把 `agenthub.yaml` 的 `execution.mode` 改为 `service`、`restart.policy: on-failure`，发布为 `order.sync@1.0.0` 后：

### 8.1 启动

```powershell
curl.exe -X POST -H "X-Admin-Token: $env:AGENTHUB_ADMIN_TOKEN" `
  -H "Content-Type: application/json" `
  -d '{"device_id": "<device_id>", "capability": "order.sync", "version": "1.0.0"}' `
  http://<server>:8000/api/processes/start
```

Agent 自然语言入口：*“让办公室电脑03持续运行订单同步程序”* → Agent 调 `start_process` 工具。

### 8.2 管理

```text
GET  /api/processes?device_id=...      实例列表（STARTING/RUNNING/STOPPING/STOPPED/FAILED）
POST /api/processes/{id}/stop          停止（terminate → 8s 宽限 → kill）
POST /api/processes/{id}/restart       重启
GET  /api/processes/{id}/logs          日志尾部（WS 从 Worker 实时取回，6s 超时 504）
```

语义铁律：**进程崩溃 ≠ Worker 崩溃 ≠ 设备消失**（§14）。意外退出按 restart 策略自动拉起（计入 restart_count，max_restarts 封顶后转 FAILED 并通知）；Worker 重启后实例由服务端与操作员重新驱动。

## 9. Worker 升级（§64/Phase 8，第一版人工触发）

```powershell
# Worker 机器上（服务仍在运行时可安全执行；结束后需重启服务）
python -c "import asyncio,sys; sys.path.insert(0, r'C:\ProgramData\AgentHub\worker'); \
from worker.updater import check_and_apply; \
print(asyncio.run(check_and_apply('http://<server>:8000', '<device_token>', r'C:\ProgramData\AgentHub', apply=True)))"

Restart-Service AgentHubWorker
```

流程：检查版本 → 下载 ZIP → 校验 `X-Checksum` → 解压 `worker.update` 暂存 → 原子换名（旧目录保留为 `worker.old`，失败自动回滚）→ **不自动重启服务**。

## 10. 常见问题

| 现象 | 处置 |
| --- | --- |
| 管理 API 全部 401 | 未配置 `AGENTHUB_ADMIN_TOKEN` 且绑定了非回环地址 —— 配置 token 或本地改绑 127.0.0.1 |
| 任务一直 PENDING | Worker 未广告该能力（看 `/api/worker-capabilities`）或全部 BUSY；等待队列有界（`TASK_OFFLINE_MAX_WAIT`，默认 600s 后转 TIMEOUT 可重试） |
| 任务 FAILED `AD_STALE` | Worker 广告过期（重连即刷新） |
| 任务 FAILED `PIN_MISMATCH` / `ARTIFACT_NOT_FOUND` / `ARTIFACT_FORBIDDEN` | 包 pin 漂移 / 输入 Artifact 丢失 / 输入被 ACL 限制 —— 均为永久失败，修正后人工重试 |
| capability 执行报 `INVALID_PACKAGE` | agenthub.yaml 与 manifest.json 的 name/version 不一致，或 entrypoint.command 含绝对路径/穿越 |
| Worker 离线 | 服务端对其任务保持原状态（断线≠终态）；ACCEPTED 超 90s 未运行会收敛为可重试的 TIMEOUT（`ACCEPTED_STALLED`） |
| 影刀能力未检测到 | 环境快照 yingdao.installed=false 时安装影刀；EXECUTOR_BUSY 失败带 retryable=true 会辅助 READ 类任务自动重试 |
