# AgentHub V1.5 实际运行手册（0 → 1）

> 适用：把一个 Python 程序包（Capability）+ 一批数据源（Artifact）派发到指定电脑（Worker）执行并拿回结果。
> 链路已在 2026-09-12 实机验收通过（`data.excel.preprocess@1.0.0`，见 ARCHITECTURE.md §20）。

---

## 0. 全景：一次任务发生了什么

```
你（群里 @机器人 或 脚本/API）
    ↓ run_capability(capability, device, inputs{输入名: [artifact_id]})
Server：创建 Task（保存 Artifact 引用）→ 解析版本/Worker → WebSocket 下发 capability.execute
    ↓
Worker（目标电脑）：
    ① 拉取能力包（缓存命中则跳过，SHA256 校验）
    ② 按 manifest 建 venv + pip install -r requirements.txt（仅首次）
    ③ HTTP 下载输入 Artifact → workspace/{input,mapping}/（checksum 校验 + 缓存）
    ④ 执行 python main.py（路径通过环境变量注入，无命令行参数）
    ⑤ 收集 output/ 产物 → 上传为 Artifact
    ↓
Server：Task SUCCESS + 产物 artifact_id → 机器人回复 / 脚本轮询到
    ↓
你：下载产物（artifact_id）
```

铁律：**Capability=程序，Artifact=数据，Task=一次执行，Worker=执行地点。**
WebSocket 只传控制；数据文件一律走 HTTP。

## 1. 一次性准备

### 1.1 环境要求

| 项 | 要求 |
|---|---|
| Python | 3.11+（server 与每台 worker 电脑都要） |
| 网络 | worker 能访问 server 地址；worker 能访问 pip 源（首装依赖用） |
| Server 依赖 | fastapi、uvicorn、sqlalchemy、alembic、pymysql（用 MySQL 时）、httpx |
| Worker 依赖 | httpx、websockets |

### 1.2 数据库（二选一）

**A. 生产 MySQL（推荐）**——迁移分两种情况：

```powershell
cd d:\Websocket\server
# 全新空库：
alembic upgrade head
# 老库（此前由服务启动 create_all 建表、缺新列，跑 upgrade 会报 1101/表已存在）：
python ..\scripts\sync_mysql_schema.py --apply   # 按 ORM 补齐缺失列
alembic stamp head                               # 结构已齐，盖到最新版本
```

MySQL 8.x 不允许 TEXT/JSON 字面量 DEFAULT，这是 1101 报错的根因，脚本已按 ORM 逐列补齐规避。

**B. 试验用 SQLite**（数据存 `server/storage/e2e_v15.db`，不动生产库）：

```powershell
$env:DATABASE_URL='sqlite:///d:/Websocket/server/storage/e2e_v15.db'
```

### 1.3 `.env` 核对（server 目录）

```ini
APP_HOST=127.0.0.1
APP_PORT=8000
AGENTHUB_ADMIN_TOKEN=...            # 管理认证（已配置）
AGENT_MODE=tool_agent               # ★ 群里对话跑 Capability 必须加这行（默认 mvp 只走关键词路由）
AGENT_CONFIRM_ACTIONS=false         # false=工具不人工确认，群里直接执行
OPENAI_API_BASE=...  OPENAI_API_KEY=...  AGENTHUB_MODEL=glm-5.3-flash   # LLM 已配置
DINGTALK_CLIENT_ID/SECRET/ROBOT_CODE=...                  # 钉钉 Stream 机器人（已配置）
SERVER_PUBLIC_URL=https://...       # 跨机 worker 用这个地址连 server
CAPABILITY_DEFAULT_TIMEOUT=1800     # 能力任务超时（秒）
```

改完 `.env` 必须重启 server。**只在群里用 MVP 关键词功能则不需要 `AGENT_MODE=tool_agent`。**

### 1.4 组网

- **同机验证**：worker `--server http://127.0.0.1:8000`。
- **跨机**（如 办公电脑02）：worker 用 `--server <SERVER_PUBLIC_URL 或局域网IP:8000>`；
  该电脑只需 Python 3.11 + `pip install httpx websockets`，无需克隆仓库（`client/` 目录整体拷过去亦可）。

## 3. Python 程序包 → Capability（适应性迭代清单）★

**需要迭代，除非你的包已满足以下契约。** 改造成本很低（参考已完成的 `D:\Slaes - 副本\preprocess_tool`）。

### 3.1 包结构（打包单元 = capability/ 目录）

```
capability/
├── manifest.json          # 能力清单（必需）
├── main.py                # 入口（必需，entrypoint=main → main.py）
├── core/ ...              # 你的业务代码
├── requirements.txt       # 依赖（建议；worker 自动建 venv 安装）
└── README.md
```

**禁止进包**：数据文件（xlsx/csv/zip）、测试输出、日志、缓存、GUI。数据一律走 Artifact。

### 3.2 manifest.json 模板

```json
{
  "name": "data.excel.preprocess",
  "version": "1.0.0",
  "runtime": "python",
  "entrypoint": "main",
  "inputs": {
    "data_dir":    {"type": "artifact_directory", "path": "input",   "required": true},
    "mapping_dir": {"type": "artifact_directory", "path": "mapping", "required": true}
  },
  "outputs": {
    "output_dir": {"type": "artifact_directory", "path": "output"}
  }
}
```

- `name` 必须三段小写 `域.资源.动作`（如 `data.excel.preprocess`）；`version` 必须 `x.y.z`。
- `inputs` 的**键名就是任务派发时的 role**；`path` 是 workspace 子目录名（多文件落同一目录）。

### 3.3 main.py 执行契约（_worker 怎么调你）

Worker 执行的是 `python main.py`（**没有命令行参数**），cwd=包根目录，注入：

| 环境变量 / params 键 | 含义 |
|---|---|
| `CAPABILITY_PARAMS`（JSON） | 含全部 inputs 键 → 已解析好的输入目录绝对路径，以及 `output_dir` |
| `CAPABILITY_EXECUTION_DIR` | 本次执行目录（result.json 写这里） |
| `CAPABILITY_OUTPUT_DIR` | 输出目录（= `<exec>/output`，已自动创建） |

**你的 main.py 要做的事（全部）：**

```python
import json, os, sys
from pathlib import Path

def _params() -> dict:
    raw = os.environ.get("CAPABILITY_PARAMS", "")
    try:
        data = json.loads(raw)
        return data if isinstance(data, dict) else {}
    except ValueError:
        return {}

def main() -> int:
    p = _params()
    input_dir  = Path(p["data_dir"])      # 与 manifest.inputs 键名一致
    output_dir = Path(p["output_dir"])    # 已存在，直接写
    # ...你的业务逻辑：读 input_dir，写 output_dir ...
    if not any(output_dir.iterdir()):
        print("ERROR 没有产出", file=sys.stderr)
        return 1                          # 退出码非 0 → 任务 FAILED
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

产物两种报法（二选一）：
1. **直接写进 `output_dir`**（推荐）——worker 自动扫描上传（跳过 `~$`/`__tmp_`/backup）；
2. 精确控制：写 `<CAPABILITY_EXECUTION_DIR>/result.json`：
   `{"artifacts": [{"path": "output/结果.xlsx", "name": "结果.xlsx", "type": "file"}]}`（path 相对 execution dir）。

成功判据 = **退出码 0 且有产物**。

### 3.4 本地冒烟（改包后先在本机自测，双模式同代码）

```powershell
cd <你的包根目录>
# CLI 模式（如包里 main.py 也支持 argv）
python capability\main.py --input sandbox\fixtures\tiny --mapping sandbox\mappings --output sandbox\output
# AgentHub 模式模拟（与 worker 注入完全一致）
$env:CAPABILITY_PARAMS='{"data_dir":"<输入目录>","mapping_dir":"<映射目录>","output_dir":"<输出目录>"}'
$env:CAPABILITY_EXECUTION_DIR='<输出目录>'
python capability\main.py
```

### 3.5 打包

`build.py`（放在仓库根，打包 capability/ 整目录，manifest 在 zip 根）：

```python
import json, hashlib, zipfile
from pathlib import Path
CAP = Path("capability"); DIST = Path("dist"); DIST.mkdir(exist_ok=True)
m = json.loads((CAP / "manifest.json").read_text(encoding="utf-8"))
zp = DIST / f"{m['name']}-{m['version']}.zip"
with zipfile.ZipFile(zp, "w", zipfile.ZIP_DEFLATED) as zf:
    for p in sorted(CAP.rglob("*")):
        if p.is_file() and "__pycache__" not in p.parts:
            zf.write(p, p.relative_to(CAP).as_posix())
print(zp, hashlib.sha256(zp.read_bytes()).hexdigest())
```

### 3.6 适应性迭代自查清单

```
[ ] 有 manifest.json（三段名 / semver / runtime=python / entrypoint=main）
[ ] main.py 从 CAPABILITY_PARAMS 读路径（或兼容 argv），不硬编码、不弹 GUI、不人工选目录
[ ] 输入只读；输出只写 output_dir；文件名不含 ~$ / __tmp_ 前缀
[ ] requirements.txt 锁定依赖（worker 联网 pip 装；内网需配 pip 本地源）
[ ] 包里没有数据文件 / 日志 / 缓存 / __pycache__
[ ] 本地 AgentHub 模式模拟跑通，退出码 0 且 output/ 有文件
```

## 4. 注册并发布能力（每版一次）

```powershell
$token = "..."; $zip = "dist\data.excel.preprocess-1.0.0.zip"

# ① 创建能力（JSON）
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/api/capabilities' `
  -Headers @{ 'X-Admin-Token' = $token } -ContentType 'application/json' `
  -Body '{"name":"data.excel.preprocess","runtime_type":"PYTHON","display_name":"Excel 预处理"}'

# ② 上传包（DRAFT）—— multipart 必须用 curl.exe（PS 的 -InFile 不发 multipart）
$resp = curl.exe -s -X POST "http://127.0.0.1:8000/api/capabilities/data.excel.preprocess/versions" `
  -H "X-Admin-Token: $token" -F "file=@$zip"
$verId = ($resp | ConvertFrom-Json).id

# ③ 发布
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/api/capability-versions/$verId/publish" `
  -Headers @{ 'X-Admin-Token' = $token }
```

更省事：直接跑 `python scripts\e2e_v15.py`（它内部完成 ①②③ + 后面所有步骤）。

发新版本：改 manifest `version` → 重新 build → 重复 ②③（旧 Task 仍锁定旧版本，不漂移）。

## 5. 上传数据源（Artifact）

**方式一：后台页面注册（推荐）**

浏览器打开 `http://<server地址>:8000/` → 右上角填入 AGENTHUB_ADMIN_TOKEN → 「数据源」页签：

1. 输入服务器本地目录（如 `D:\数据\源数据`）→ 点「扫描目录」
2. 勾选文件 → 点「上传选中 → 注册 Artifact」→ 表格里出现 **artifact_id**（可一键复制）
3. 下方"已注册 Artifact"列表可随时复制 ID / 下载

原理：server 直接读本地磁盘登记（不经浏览器中转），48MB 的 xlsx 也秒级注册。
仅列第一层文件（自动跳过 `~$` 锁文件与隐藏文件）。

**方式二：脚本上传**

```powershell
cd d:\Websocket
python scripts\upload_artifact.py "D:\数据\订单样例.xlsx"          # 单文件
python scripts\upload_artifact.py "D:\数据\映射表目录"              # 整目录（每文件一个 Artifact）
```

输出示例（**记下 artifact_id，role 对应关系是你自己定的**）：

```
art_f117df24e8f74773     订单样例.xlsx        6649B      ← role: data_dir
art_cb991bf23626492f     店铺对应平台.xlsx     6187B      ← role: mapping_dir
art_860347c1049642c3     商品资料.xlsx        6127B      ← role: mapping_dir
...
```

> 同一 role 传多个 artifact 会全部落到同一个 workspace 子目录（如 4 张映射表 → mapping/）。
> 注意：PowerShell 5.1 的 Invoke-RestMethod 发中文 JSON body 会乱码（GBK）——用上面的脚本/页面，
> 或 curl.exe（`-H "Content-Type: application/json; charset=utf-8"` 且 body 存为 UTF-8 文件）。

## 6. 派发任务并拿结果（三种方式）

### 方式 A：群里对话（推荐日常使用）

前提：`.env` 有 `AGENT_MODE=tool_agent` 且 server 已重启。

1. 群里 @机器人，一句话说清 **能力名 + 版本(可选) + 哪台电脑 + 哪些数据**：

   > 用 data.excel.preprocess 1.0.0 在 办公电脑02 处理数据，
   > inputs：data_dir=[art_f117df24e8f74773]，mapping_dir=[art_cb991bf23626492f, art_860347c1049642c3, ...]

2. 机器人回复（任务执行完才回，含产物清单）：

   > 已完成。任务 task_xxx SUCCESS，产物：[订单样例.xlsx](artifact_id=art_xxx)

3. 拿结果：

   ```powershell
   python scripts\download_artifact.py art_xxx --out D:\结果
   ```

提示：不确定能力名/输入名时，先问机器人“有哪些能力”/“看下 data.excel.preprocess 的详情”（list_capabilities / get_capability 工具）。
**当前边界**：群里无法直接传文件——先用第 5 步脚本上传拿到 artifact_id，再在消息里引用。

### 方式 B：脚本一键（回归验证）

复制 `scripts/e2e_v15.py`，改顶部 `CAP_NAME / DATA_FILE / MAPPING_DIR / DEVICE_NAME` 后运行；它覆盖发布→上传→建任务→等待→下载校验全链路。

### 方式 C：API 直调

```powershell
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/api/tasks' -Headers $h `
  -ContentType 'application/json' -Body (@{
    name = "预处理"; execution_type = "CAPABILITY"; capability_version = "1.0.0"
    target_device_id = "<device_id>"            # 省略则平台自动选在线 worker
    steps = @({ command = "data.excel.preprocess"; params = @{} })
    input_artifacts = @(
      @{ artifact_id = "art_f117..."; role = "data_dir" }
      @{ artifact_id = "art_cb99..."; role = "mapping_dir" }
    )
  } | ConvertTo-Json -Depth 5)

# 轮询
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/tasks/task_xxx' -Headers $h
# 产物
python scripts\download_artifact.py --list --task-id task_xxx
```

## 7. 观察与排查

| 看什么 | 位置 |
|---|---|
| Worker 执行日志 | 控制台 + `client/logs/worker.log` |
| 本次执行现场 | `~/.devicelink/work/executions/<attempt_id>/`（input/mapping/output/context.json/params.json） |
| 任务事件流 | `GET /api/tasks/{id}` 的 events（progress 每步都有） |
| Server 日志 | uvicorn 控制台 |

**错误码速查**：

| 错误码 | 含义 | 常见原因/处理 |
|---|---|---|
| CAPABILITY_NOT_FOUND / CAPABILITY_UNAVAILABLE | 能力不存在/无 PUBLISHED 版本 | 先做第 4 节发布 |
| DEVICE_NOT_FOUND | 设备名/ID 不对 | 用 list_devices 确认在线设备名 |
| ARTIFACT_NOT_FOUND | 引用的 artifact_id 不存在 | 上传脚本输出重新核对 |
| ARTIFACT_DOWNLOAD_FAILED | worker 下载失败 | server 不可达/令牌失效；看 worker.log |
| ARTIFACT_CHECKSUM_MISMATCH | 下载内容校验失败 | 重新上传 artifact 再派发 |
| DOWNLOAD_FAILED / CHECKSUM_FAILED / INVALID_PACKAGE / INSTALL_FAILED | 能力包拉取/安装失败 | 看 worker.log；包损坏则重新 build+上传 |
| PYTHON_ENV_CREATE_FAILED / DEPENDENCY_INSTALL_FAILED | venv/pip 失败 | worker 机器 pip 源不通；看 stderr 尾部 |
| CAPABILITY_EXECUTION_FAILED | 业务脚本失败 | event 的 error_message=stderr 尾 800 字符；对照 executions 目录现场 |
| INVALID_PARAMS | 缺 manifest required 输入 | inputs 里补齐对应 role |
| ARTIFACT_UPLOAD_FAILED | 产物回传失败 | 检查 server 可达后重派 |

**缓存与重跑**（`~/.devicelink/work/`）：

| 缓存 | 命中条件 | 强制刷新 |
|---|---|---|
| `capabilities/<名>/<版>` | 包 checksum 一致 | 删目录，或发布新版本 |
| `envs/<名>/<版>` | requirements 哈希一致 | 删目录 |
| `artifact_cache/<checksum>` | 内容一致 | 删目录 |

正常迭代不需要手动清缓存：改代码→改版本号→重发布即全链路刷新。
